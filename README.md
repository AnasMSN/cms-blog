# Oleh-oleh CMS

A configurable website for souvenir (oleh-oleh) brands, with an admin panel the shop owner can use without touching code. Built as a portfolio / reusable template for UMKM website projects.

Demo brand included: **Sari Priangan** (fictional oleh-oleh shop from Bandung & Garut).

## Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | Next.js 16 (App Router) | Fast pages, good SEO, one codebase for site + admin |
| CMS / backend | Payload CMS 3 | Admin panel, auth, drafts, image resizing generated from config |
| Database | SQLite (libSQL) | One file, no DB server; can move to Turso for serverless |
| Hosting | Docker + Caddy on a small VPS | Cheap, automatic HTTPS, full control |
| CI/CD | GitHub Actions + GHCR | Typecheck, migration check, build, deploy with health check |

## Quick start (local)

Requirements: Node.js 20.9+ (22 recommended).

```bash
cp .env.example .env          # then set PAYLOAD_SECRET (openssl rand -hex 32)
                              # and DATABASE_URI=file:./data/site.db
npm install
npm run seed                  # demo content + admin user
npm run dev
```

- Website: http://localhost:3000
- Admin: http://localhost:3000/admin
- Default admin: `admin@example.com` / `ganti-password-ini` (set `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` before seeding to change it)

Reset demo content: `npm run seed -- --force`

## What the client can change in the admin

| Admin menu | What it controls |
|---|---|
| Katalog → Produk | Products: name, price, unit, photos, specs, badges, marketplace links, draft/publish, featured on home |
| Katalog → Kategori | Product categories and their order |
| Konten → Cerita & Budaya | Heritage / culture articles, linked to products |
| Konten → Foto & Media | Photo library (auto-resized to WebP) |
| Halaman → Beranda | Hero text & image, highlights, section titles, about teaser, testimonials |
| Halaman → Tentang Kami | About page and business timeline |
| Pengaturan → Pengaturan Situs | Brand name, logo, **site colours**, WhatsApp number & message template, address, hours, maps, marketplaces, social links, SEO |
| Pengaturan → Pengguna | Users. **Admin** = everything; **Editor** = content only |

## Project structure

```
src/
  access/            who can read / edit what
  collections/       Products, Categories, Stories, Media, Users
  globals/           Home, About, Settings (single-page content)
  migrations/        database migrations (commit these!)
  seed/              demo content + placeholder image generator
  app/(frontend)/    public website pages + styles.css
  app/(payload)/     admin panel & API (generated by Payload)
  app/healthz/       health check used by Docker & deploys
deploy/Caddyfile     HTTPS reverse proxy
scripts/             server setup, backup, restore
.github/workflows/   CI and deploy pipelines
docs/OPERATIONS.md   full DevOps runbook
```

## Adding a field (the one rule to remember)

1. Edit a file in `src/collections` or `src/globals`.
2. `npm run dev` — the local DB updates automatically.
3. `npm run generate:types`
4. `npm run payload migrate:create describe-your-change`
5. Commit the new file in `src/migrations`. Production applies it on boot.

CI fails if you change the schema without step 4.
